# 起訴書去識別化人工審查 UI

這是只使用 Python 標準函式庫的本機審查工具。預設讀取民國 114 年起訴書的 clean corpus，僅監聽 `127.0.0.1`，不會把內容傳送到外部服務。

## 啟動

在專案根目錄執行：

```powershell
python -X utf8 review_ui/server.py
```

瀏覽器會自動開啟 <http://127.0.0.1:8765>。以 `Ctrl+C` 停止服務。

不自動開啟瀏覽器：

```powershell
python -X utf8 review_ui/server.py --no-browser
```

首次啟動會建立 100 筆可重現的風險優先樣本：先納入只有 1–2 筆的長尾案由，再納入全文最長的 5%，最後以固定種子補足。可在介面內調整樣本數與種子；重新抽樣不會刪除既有審查紀錄。

## 保存位置

審查決定、問題標籤、備註與每次修改歷史保存在：

```text
data/review/indictment_reviews.sqlite3
```

介面可匯出 Excel 相容的 UTF-8 CSV 或 JSONL。SQLite 資料庫與匯出檔含法務部來源代碼，應視為 restricted data。

介面中的「結構化證物」取自起訴書正文。`content` 為空代表公開書類只有證物名稱或卷頁引用，並沒有提供原始偵查卷或證物檔案。

介面中的「本地模型 Verify」是第二層提示：模型只讀取 clean text、不直接修改資料，且畫面只顯示經機器規則確認仍具可行動性的警示。它用來協助人工聚焦，不能視為通過或退回的自動判定。執行方式見根目錄 `README.md`。

## 審查建議

- `通過`：未發現身分資訊殘留，且去識別化未破壞案件法律語意。
- `退回`：有姓名、地址、機構、聯絡資訊等殘留，或出現過度遮罩、法律語意受損。
- `待確認`：需要另一位審查者判斷。
- 退回時勾選問題類型，並在備註填寫殘留文字或所在段落，方便後續修正規則。

鍵盤快捷鍵：`1` 通過、`2` 退回、`3` 待確認、`Ctrl/Command + Enter` 儲存、方向鍵切換案件。

## 起訴書＋判決書案件配對審核台

配對 UI 使用獨立的程式、資料庫與 `8766` port，不會改動前述起訴書審核紀錄：

```powershell
python -X utf8 review_ui/pair_server.py
```

瀏覽器開啟 <http://127.0.0.1:8766>。每個審核單位是一組起訴書與判決書，畫面包含跨文書人物代號、整合犯罪事實、保留來源標籤的事證物證，以及兩份文書各自的正規化原文與去識別化文本。判決批次仍在執行時，可按「同步最新結果」載入新 checkpoint。

配對審核決定、問題標籤、備註及歷史保存在：

```text
data/review/pair_reviews.sqlite3
```

此介面只監聽 `127.0.0.1`。原文、人物 mentions、SQLite 與匯出檔均屬 restricted data，不可直接部署為公開網站。
